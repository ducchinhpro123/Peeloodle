# Domain docs

## Layout and reading rules

This is a single-context project.

Before exploring:

- Read root `CONTEXT.md`.
- Read relevant decisions under `docs/adr/`.

If these do not exist, proceed silently. Do not suggest creating them
upfront; domain-modeling creates them when terms or decisions resolve.

## Vocabulary

Use the domain terms defined in `CONTEXT.md` in issues, proposals,
hypotheses, and tests. Avoid synonyms the glossary explicitly rejects.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## Decisions

Explicitly flag any proposal that contradicts an existing ADR,
identifying the ADR and explaining why it should be reconsidered.
